# Blog Publishing & Maintenance Guide

A quick reference and checklist for writing, editing, and deploying transmissions on **binbot.dev**.

---

## ⚠️ The Golden Rule

> **Always edit files in `content/`, NEVER in `posts/` or `blog/`!**
>
> Files inside `posts/*.html` and `blog/index.html` are **generated build artifacts**. Whenever `./deploy.sh` or `build.py` runs, it will compile `content/` and **completely overwrite** any manual changes made to the HTML files.

---

## 📋 Blog Workflow Checklist

### 1. Creating a New Post
Run the helper script from the repository root:
```bash
./new-post.sh "Your Post Title Here"
```
- Creates `content/blog/YYYY-MM-DD-slug.md` with pre-filled frontmatter.
- Automatically opens the post in your configured editor (`nvim`).

### 2. Editing an Existing Post
Use the new interactive editor helper:
```bash
# Fuzzy-search all posts with fzf:
./edit-post.sh

# Or jump straight to a specific post:
./edit-post.sh bread
./edit-post.sh 2026-09-02
```
Or open the source file directly:
```bash
nvim content/blog/2026-09-02-baking-log-batch-1-honey-white-sandwich-bread.md
```

### 3. Adding Images and Media
1. Drop media into the `media/` directory:
   ```bash
   cp ~/Downloads/photo.jpg media/my-photo.jpg
   ```
2. Reference it in your post Markdown:
   ```markdown
   ![Description of photo](/media/my-photo.jpg)
   ```
3. Audio files can be embedded with the custom player tag:
   ```markdown
   [audio: /media/track.mp3 | Track Title]
   ```
> **Privacy Note:** `build.py` automatically strips all EXIF, GPS, camera, and device metadata from images in `media/` during every build.

### 4. Preview / Test Locally (Optional)
Build without deploying to verify formatting:
```bash
python3 build.py
```
To view in a browser locally:
```bash
python3 -m http.server 8080
# Visit http://localhost:8080 in your browser
```

### 5. Deploy to the Raspberry Pi
When you are ready to publish:
```bash
./deploy.sh
```
What `./deploy.sh` does automatically:
1. **Rebuilds static HTML** from all Markdown source files.
2. **Queries live hardware telemetry** from the Pi (`pipi`) to update `/blog/index.html`.
3. **Rsyncs** the clean website files to `/var/www/retro-blog/` on the Pi.
4. **Git stages, commits, and pushes** the latest build and transmissions to GitHub & Codeberg.

## 🗂 Directory Map

| Directory / File | Purpose | Editable? |
| :--- | :--- | :--- |
| `content/blog/*.md` | Markdown source for all blog posts | ✅ **Yes (Edit posts here)** |
| `content/*.md` | Markdown source for `about.md`, `audio.md`, `cv.md` | ✅ **Yes** |
| `media/` | Images, audio files, and attachments | ✅ **Yes** |
| `style.css` / `script.js` | Site styling and retro Pure Data UI interactions | ✅ **Yes** |
| `new-post.sh` | Helper script to scaffold new posts | ✅ Script tool |
| `edit-post.sh` | Helper script to find & edit existing posts | ✅ Script tool |
| `deploy.sh` | Build, rsync to Pi, and git sync script | ✅ Script tool |
| `posts/*.html` | Compiled HTML posts generated by `build.py` | ❌ **No (Auto-generated)** |
| `blog/index.html` | Compiled blog archive & telemetry generated by `build.py` | ❌ **No (Auto-generated)** |
| `rss.xml` | Compiled RSS 2.0 feed generated by `build.py` | ❌ **No (Auto-generated)** |
